Chapter 02 of 12

Write a clean request before you send it

Dictate or type the ask, run it through a polish and a prompt-engineer pass, read it back, then send.

Principle

Every request to a bot or any AI is cleaned before it is sent. The owner's practice (in his words, 2026-10-22): dictate with Wispr Flow, or type when he needs to think; when done, run Wispr Flow's transformers Option+1 (Polish) and Option+2 (Prompt engineer). Reading the polished or prompt-engineered version also confirms his own understanding of the ask and lets him check it's what he actually wants.

Why it matters

  • It is a verification loop. The rewrite is a second reading of your own intent. If the cleaned text says something you did not mean, you caught a misunderstanding before any bot acted on it.
  • Fewer correction rounds. A vague ask produces a plausible but wrong answer, then a correction, then a redo. A clean ask removes most of those loops. Inferred the effect is largest on long research or ticket requests.
  • Better downstream text. Bots often quote the owner's words in handoffs (chapter 03). Clean words make clean approvals.

Worked examples

Example

The steps

  1. Dictate the request in Wispr Flow, or type it when you need to think it through.
  2. Select it and press Option+1 (Polish) for grammar and clarity.
  3. For anything non-trivial, press Option+2 (Prompt engineer) to structure it: goal, context, constraints, expected output.
  4. Read the result. Ask: is this what I actually want? Fix anything that drifted.
  5. Send.
Example

Before and after <span class="badge-muted">Illustrative</span>

This pair is written for the guide; it is not a recorded message.

Raw dictation:

ok so the api info thing shows wrong version i think and the builder too, we had open spec for this right so why, if its a bug put it in the old ticket

After Polish + Prompt engineer:

Check https://k8s.dflow.sh/api/v1/info. The version and the default builder image look wrong.
1. Confirm whether each value is wrong, and why.
2. Explain why our OpenAPI/OpenSpec contract did not catch it.
3. If it is a bug, add it to the existing version-mismatch bug ticket (don't create a new one).

Reading the second version, the owner can see he is asking for three things, including a root-cause question he only implied.

Templates

Self-check before sending

Before I send:
[ ] Goal in one sentence?
[ ] Context the bot can't know (product, environment, constraints)?
[ ] Exactly which action I approve (create / update / draft only)?
[ ] What I want back (link, list, decision, draft)?
[ ] Does the cleaned version say what I actually mean?

Pitfalls

  • Sending the prompt-engineered text without reading it. The read-back is the point.
  • Letting the rewrite add scope you didn't ask for (extra deliverables, invented constraints). Delete them.
  • Over-engineering one-line asks. Polish alone is enough for "link to the ticket".
